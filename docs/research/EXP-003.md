## EXP-003b — crop strategy for the composed baseline (G6 Phase 7, RUN)

**Question.** The composed baseline crops each changed region from T2 and tags it
with RemoteCLIP. Does *how* the crop is taken change the tag? Three strategies,
**same regions, same semantic worker**:

| Strategy | Crop |
|----------|------|
| `tight` | exact changed-region bbox (original behaviour) |
| `expanded` | bbox padded 75 % each side → surrounding context |
| `mask_aware` | expanded crop, non-changed pixels dimmed to 0.35× |

Implemented as `run_composed_semantic_change(..., crop_strategy=...)`
(`apps/backend/app/services/semantic_change_baseline.py`), default `tight`
(preserves existing behaviour + tests). Harness:
`evaluation/scripts/exp003b_semantic_change_crops.py`.

**Setup.** Pair `data/demo/temporal/{t1,t2}.tif` (LEVIR building-change sample,
EPSG:32650). 6 changed regions (~1.2–1.6 k px each). CPU, RemoteCLIP ViT-B/32.
~45 s per strategy. **No ground-truth semantic labels on this pair** → this is a
**stability / behaviour** comparison, **not** a correctness measurement.

**Results** (`evaluation/reports/exp003b_crops_*.json`):

| Region | tight | expanded | mask_aware | 3-way agree |
|:------:|-------|----------|------------|:-----------:|
| 1 (1638 px) | *no notable change* | building demolition | building demolition | ✘ |
| 2 (1294 px) | building demolition | building demolition | building demolition | ✔ |
| 3 (1271 px) | building demolition | building demolition | building demolition | ✔ |
| 4 (1263 px) | building demolition | building demolition | building demolition | ✔ |
| 5 (1244 px) | building demolition | building demolition | building demolition | ✔ |
| 6 (1209 px) | new vegetation | new buildings | building demolition | ✘ |

- **Cross-strategy agreement: 4 / 6 regions (0.667).**
- **`expanded` / `mask_aware` rescued region 1** — `tight` called the largest
  changed region "no notable change" (rank-1 margin only 0.096); adding context
  flipped it to the plausible "building demolition".
- **Region 6 is unstable under every strategy** — a small, genuinely ambiguous
  patch. Kept as a **failure case**, not smoothed over.
- **`tight` produces the lowest rank-1 margins** (r3 = 0.008, r6 = 0.033) → the
  similarity signal is weak on bare crops.
- **`mask_aware` collapses toward one label** — all 6 regions → "building
  demolition". On a LEVIR building-change pair that dominant class is plausible,
  but the monoculture is a **risk**: it would hide genuine variety on a mixed
  scene. Documented failure mode.

**Provisional decision.** Make **`expanded`** the composed-baseline default: it
fixed the `tight` miss (r1), kept region 6 distinct from the demolition
monoculture, and gave the most usable rank-1 margins. Keep `tight` and
`mask_aware` selectable. **Not changing the default in code yet** — one 6-region
demo pair is not enough evidence; revisit with a labelled LEVIR-CC sample in
EXP-003a on the remote box, then set the default with a measured caption metric.

**What this is not.** Not a learned temporal VLM. Not validated semantic
reasoning. RemoteCLIP tags are similarity to fixed phrases, not calibrated
labels. No confidence value produced.
