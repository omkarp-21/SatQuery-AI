# EXP-007 — Geospatial safeguard stress test

> Registry: `docs/19_EXPERIMENT_REGISTRY.md#EXP-007`. Hypothesis **H5**
> (geospatial validation reduces invalid / misleading paired analysis).
> Status: **RUN (2026-09-01)** — deterministic, local. Safeguards were **not**
> weakened to make any malformed input pass.
> Implementation: `apps/backend/tests/test_exp007_geospatial_stress.py` (15 cases).

## Method

Battery of malformed / pathological inputs against `validate_geotiff`,
`check_pair_compatibility`, and the `/change` co-registration gate. Synthetic
rasters with known geodata (`tmp_path`); no downloads. Each case asserts the
**expected** safeguard behaviour.

## Notes / threats to validity

- All cases are **synthetic** rasters — real ISRO products may carry
  non-standard CRS tags, RPCs, or GCPs that `read_raster_meta` currently maps to
  the identity transform with a warning; a follow-up should test a real
  non-georeferenced product and an RPC-only product.
- The bomb guard uses a header-only pixel-count check, not a decoded-size check;
  a maliciously-tiled COG could still be expensive to *read* windowed — windowed
  reads are used everywhere, which bounds this in practice.
- `check_pair_compatibility` compares transforms with a `1e-6` tolerance in CRS
  units; sub-pixel misregistration below that is *not* flagged (by design — it
  would be a co-registration-quality metric, not a compatibility gate).

## Decision

**KEEP** the geospatial gate. H5 is **supported at the structural level**: every
class of invalid pair is rejected before any model runs. A *task-level* H5 result
(does the gate reduce downstream change-metric error?) still needs EXP-004 Run 2
data with deliberately-broken pairs mixed in.
