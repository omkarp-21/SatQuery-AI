# EXP-005 — Structural verifier: detection metrics

> Registry: `docs/19_EXPERIMENT_REGISTRY.md#EXP-005`. **Local, unblocked, RUN
> 2026-09-01 (G6).** Measures what `satquery_evidence.verify()` actually detects,
> and sizes the gap it leaves for a future semantic verifier.
> Harness: `evaluation/scripts/exp005_verifier_detection.py` ·
> lock test: `packages/evidence/tests/test_exp005_verifier_detection.py` (3 tests).

## Question

The verifier is **deterministic / structural only** (its own docstring +
`notes` field say so). Two numbers were missing:

1. On inputs where a **structural** defect exists, does `verify()` flag it?
   (precision / recall / F1 for structural-defect detection)
2. On inputs that are **structurally clean but semantically wrong**, how often
   does `verify()` wrongly return `SUPPORTED`? (the semantic gap — expected high)

## Method

**Corpus:** 24 hand-curated `(result, evidence, context)` cases, one bucket per
row, built to exercise every rule in `verifier.py` (`changed_fraction` range,
`mask_path` presence, `pair_co_registered`, `modality_supported`, ranking-prob
range, embedding dim, `inputs_exist`).

| Bucket | n | Definition | Expected `verify()` status |
|--------|:-:|------------|----------------------------|
| **CLEAN** | 6 | no structural defect, semantically plausible | `SUPPORTED` |
| **STRUCTURAL** | 8 | a deterministic check must fail (bad range, missing artifact, mis-registration, modality mismatch, zero-dim embedding, missing input) | `CONTRADICTED` |
| **SEMANTIC** | 6 | structurally clean, **semantically wrong** (mask flags a cloud; absurd top label; T1/T2 swapped; demolition missed at cf≈0.002; embedding from the wrong tile) | `SUPPORTED` (a miss) |
| **INSUFFICIENT** | 4 | nothing checkable (no evidence; `metadata`/`citation` evidence types with no rule) | `INSUFFICIENT_EVIDENCE` |

**Detection scoring** — positive class = "a structural defect is present":

```
TP = STRUCTURAL ∧ CONTRADICTED     FN = STRUCTURAL ∧ ¬CONTRADICTED
FP = (CLEAN∪SEMANTIC) ∧ CONTRADICTED  TN = (CLEAN∪SEMANTIC) ∧ ¬CONTRADICTED
INSUFFICIENT cases reported separately (not in the matrix).
```

## Results (2026-09-01, `evaluation/reports/exp005_verifier_*.json`)

### Structural-defect detection

| | value |
|--|--|
| confusion matrix | **TP 8 · FP 0 · TN 12 · FN 0** (+ 4 INSUFFICIENT, all correct) |
| **precision** | **1.00** |
| **recall** | **1.00** |
| **F1** | **1.00** |

Every structural check fires exactly on the defect class it is written for; no
clean or semantically-wrong case is mis-flagged as `CONTRADICTED`.

### Semantic-defect gap

| | value |
|--|--|
| SEMANTIC cases | 6 |
| missed by the structural verifier (returned `SUPPORTED`) | **6** |
| **miss rate** | **1.00** |

**The structural verifier catches 0 % of semantic defects — by construction.**
This is the number that justifies a semantic-verifier extension (below), not a
regression.

## What this number is and is NOT

- **IS:** a unit-level check that the eight structural rules trigger precisely on
  the structural defects they target, on a curated corpus (n = 24). Reproducible,
  locked by 3 tests.
- **IS NOT:** a real-world defect-coverage rate. P/R/F1 = 1.00 does **not** mean
  "the verifier catches every bad result in production" — it means the rules are
  self-consistent with their own defect definitions. Real coverage depends on how
  many production failure modes are *structural* at all (this corpus says: the
  semantic ones, which are the majority of interesting failures, are entirely out
  of scope).
- Corpus is small and author-built → **selection bias toward rule-shaped cases**.
  Grow it with real `/analyze` failures before quoting these numbers anywhere
  outside this file.

## Semantic-verifier extension points (created, not implemented)

`verify()` is the substrate. A future `verify_semantic(result, evidence, context)`
would add, each returning a `Check` and never a bare confidence number:

| Check | Signal | Needs |
|-------|--------|-------|
| `independent_rederivation` | re-run the claim with a different method (e.g. image-difference vs ChangeFormer) and compare | a second cheap method per task |
| `optical_sar_agreement` | do the optical and SAR paths agree on the same scene? | both modalities present (D) |
| `cross_model_consistency` | do two VLMs give compatible answers to the same VQA? | ≥ 2 VQA models (A — blocked) |
| `temporal_direction_sanity` | does the described change direction match T1→T2 dates? | date metadata (present) |
| `label_plausibility` | is the top label in the scene's plausible label set (prior)? | a per-region class prior |

These are **design hooks**. None is built in G6 — building them needs the A/B
models (blocked) and labelled data. `CONFIDENCE_PLAN.md` consumes the verifier
**status** (not a score) as one calibration input (EXP-C1).

## EXP-005b — model-independent semantic verifier (G7 Phase 8, RUN 2026-09-01)

G6/EXP-005 quantified the gap (structural verifier misses 100 % of semantic
errors). G7 builds the **first** semantic verifier — `verify_semantic()` in
`packages/evidence/src/satquery_evidence/semantic_verifier.py` — and measures it.

### What it does (and deliberately does not)

`verify_semantic(result, evidence, context)` is **deterministic and
model-independent**. It catches **internal semantic incoherence** by
cross-referencing what is already present:

| Check | Fires when |
|-------|-----------|
| `claim_matches_evidence_number` | a % in the model's description disagrees with an evidence `changed_fraction` |
| `claim_label_in_evidence` | a quoted `resembles 'X'` label appears in **no** evidence item |
| `temporal_direction_coherent` | forward-time phrasing ("new", "constructed", "expansion", …) on a **T1 > T2** (swapped) pair |
| `spatial_region_in_bounds` / `lonlat_valid` | a region bbox falls outside the image, or lon/lat out of range |
| `region_area_sane` | a "changed region" covers ≥ 95 % of the scene |
| `region_areas_within_total` | region areas sum to > 110 % of the reported total changed area |

It does **NOT** judge real-world label correctness. Checks that need a second
model or another modality are **declared unavailable** in the result
(`coverage_unavailable`): `independent_model_agreement` (EXP-002),
`optical_sar_agreement` (EXP-C2), `grounding_roundtrip`.

### Method

Curated corpus, 34 cases: **COHERENT 8 / INCOHERENT 10 / BEYOND_SCOPE 6 /
NOT_ENOUGH 4**. `BEYOND_SCOPE` = wrong only in a way an independent model could
catch (absurd-but-present label, cloud flagged as change, missed demolition).
Positive class = "a model-independent semantic incoherence is present".
Harness: `evaluation/scripts/exp005b_semantic_verifier.py`; lock tests:
`packages/evidence/tests/test_semantic_verifier.py` (9).

### Results (`evaluation/reports/exp005b_semverif_*.json`)

| | value |
|--|--|
| confusion matrix | **TP 10 · FP 0 · TN 14 · FN 0** (+ 4 NOT_ENOUGH, all correct) |
| **precision / recall / F1** (internal-incoherence detection) | **1.00 / 1.00 / 1.00** |
| **BEYOND_SCOPE residual miss rate** | **1.00** (6/6 — needs an independent model, as expected) |

### Reading

- The semantic verifier catches **every** internal contradiction in the corpus
  (number, label, temporal direction, geometry, area arithmetic) with **no false
  positives** on coherent or beyond-scope cases.
- It still misses **all 6** "the label is just wrong" cases — that residual gap
  needs EXP-002 (a second VQA model → `independent_model_agreement`) and EXP-C2
  (optical↔SAR agreement). This is the honest boundary of a model-independent
  verifier.
- **Same caveat as EXP-005:** n=34, author-curated → this proves the six checks
  fire on their target defect classes, **not** a real-world coverage rate. Grow
  the corpus with real `/analyze` outputs before quoting elsewhere.

### Integration

`verify_semantic()` is wired into `COMPOSED_SEMANTIC_CHANGE_BASELINE` as an
**additive** `semantic_verification` field (`ComposedSemanticChangeResult`), fed
the assembled description + regions + evidence + scene geometry. On the demo pair
its own output is `COHERENT` (the rule-assembled description is internally
consistent by construction — a useful smoke check that the plumbing does not
corrupt numbers/coords). No `/analyze` contract change beyond the new optional
field. No confidence number.

## Verdict

- **Structural verifier (EXP-005): P/R/F1 = 1.00 on n=24 — MEASURED. VALIDATED
  (structural).**
- **Semantic verifier (EXP-005b): P/R/F1 = 1.00 on n=34 for model-independent
  incoherence — MEASURED. Experimental — INTEGRATED into the composed baseline.**
- **Residual semantic gap: label-correctness errors (miss rate 1.00 on
  BEYOND_SCOPE) — needs EXP-002 + EXP-C2.**
- No confidence number emitted.
