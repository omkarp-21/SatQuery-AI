# EXP-004 — Optical-only vs CROMA-joint vs DOFA-fused

> Registry entry: `docs/19_EXPERIMENT_REGISTRY.md#EXP-004`. Hypothesis: **H3**
> (optical + SAR improves reliability for suitable tasks vs optical-only).
> Status: **DONE (G12, 2026-09-02).** Run 1 = synthetic sanity check. **Run 2 =
> real DFC2020 probe** — CROMA joint 0.793 vs optical 0.726 macro-F1 (+0.067, not
> significant at n=200); DOFA concat-fusion no gain. **KEEP CROMA** for the
> optical–SAR path. Sanity-scale (600/986 patches) — a real integrated number,
> not a full benchmark. See Run 2 below.

## The three numbers (`docs/18`)

- **Paper (#1):** CROMA / DOFA report SOTA-class linear-probe results on BigEarthNet,
  DFC2020, GEO-Bench (2023–24). Not reproduced by us.
- **Our reproduction (#2):** both encoders **REPRODUCED** on CPU (G1.6,
  `runtime_validation.md`) — embeddings only.
- **SatQuery (#3):** **MEASURED (G12).** DFC2020 dominant-land-cover probe,
  frozen CROMA `joint_GAP` → linear probe → **macro-F1 0.793** (n_eval=200,
  seed 20260902, CPU). Optical-only baseline 0.726. Sanity-scale, not a full
  DFC2020 benchmark. Reported as an *integrated-system* number only.

## Run 1 — controlled synthetic-signal sanity check  *(NOT a benchmark)*

### Why synthetic

The experiment needs co-registered **labelled Sentinel-1 + Sentinel-2** patches.
The smallest preprocessed real option (CROMA's `DFC_preprocessed.pt`, DFC2020) is
**11.2 GB**; the brief forbids large blind downloads. reBEN shards were not pulled.
So Run 1 uses a small synthetic paired set to **validate the machinery** and get a
**directional** H3 signal; Run 2 (below) is the real one.

### Setup (recorded)

| Field | Value |
|-------|-------|
| Dataset | **synthetic** — S1 `(N,2,120,120)`, S2 `(N,12,120,120)`, values in [0,1] |
| Signals | two independent binary signals: `signal_opt` injected only in an S2 band (bright square), `signal_sar` injected only in an S1 (VH) region (elevated backscatter) |
| Split | train N=240, test N=160 (fresh draw, same generator) |
| Seed | 20260901 |
| Hardware | RTX 3050 Ti host, **CPU only** (torch 2.13.0+cpu), `.venvs/croma` |
| Arms | (1) optical-only = CROMA `optical_GAP`; (2) **CROMA joint** = `joint_GAP`; (3) DOFA optical-only = S2 `forward_features`; (4) **DOFA fused** = S2 ⊕ S1 features concatenated |
| Probe | `sklearn.LogisticRegression(max_iter=2000, C=1.0)` on **frozen** features |
| Metric | balanced accuracy, recovering each signal separately |
| Runtime | CROMA feature extraction 155 s / 400 samples; DOFA 95 s; total 252 s |

### Result (sanity check — do not cite as a benchmark)

| Arm | recover `signal_opt` | recover `signal_sar` | feat dim |
|-----|:--------------------:|:--------------------:|:--------:|
| optical-only (CROMA `optical_GAP`) | **1.00** | **0.485** (chance) | 768 |
| **CROMA joint (`joint_GAP`)** | 1.00 | **1.00** | 768 |
| DOFA optical-only (S2 feat) | **1.00** | **0.502** (chance) | 768 |
| **DOFA fused (S2 ⊕ S1)** | 1.00 | **1.00** | 1536 |

### What it does / does not show

- **Does:** the full 3-arm pipeline (real CROMA + DOFA encoders → frozen features →
  linear probe → metric) runs end to end on the laptop. A signal that lives only
  in the SAR channels is **recovered by the joint/fused arms and is at chance for
  optical-only arms** — the mechanism H3 depends on is present in both CROMA's
  native joint encoder and DOFA's concat fusion.
- **Does NOT:** say anything about real land-cover accuracy, or how much SAR helps
  on a real task, or which of CROMA/DOFA is better — they are indistinguishable
  here (both 1.00). The injected signal is clean and separable by construction.

### Decision

**INVESTIGATE → proceed to Run 2.** No KEEP/REJECT yet. H3 is **not** supported or
rejected by a synthetic check.

## Run 2 — the real benchmark (DONE 2026-09-02, G12)

**Unblocked by the G11 recipe.** `HF_HUB_ENABLE_HF_TRANSFER=1` + a non-gated HF
mirror (`125oii/dfc2020`) pulled the DFC2020 `ROIs0000_validation` split as
separate zips — `s1_validation.zip` 947 MB, `s2_validation.zip` 633 MB,
`dfc_validation.zip` 6 MB — in **~2.5 min total**. Same wall that blocked this for
four gates; same fix that cleared A/B in G11. No synthetic substitution.

### Setup (recorded — `evaluation/datasets/dfc2020_exp004_split.json`)

| Field | Value |
|-------|-------|
| Dataset | IEEE GRSS **DFC2020** `ROIs0000_validation` (986 patches, 256×256), via non-gated mirror `125oii/dfc2020` |
| Modalities | S1 GRD 2-band (VV, VH) dB; S2 L1C 13-band → **12 kept** (drop B10 cirrus); DFC high-res 10-class label |
| Task | **single-label patch classification — dominant DFC land-cover class** (8 classes present: Forest, Shrubland, Grassland, Wetlands, Croplands, Urban, Barren, Water) |
| Split | deterministic shuffle, seed 20260902 → **400 train / 200 eval**, patch ids frozen in the split file |
| Preprocessing | raw GeoTIFF → band select → nearest-resize 128 px → per-sample per-channel (mean ± 2σ) clip-normalise at feature time |
| Encoders | **frozen** CROMA-base (MIT) + DOFA ViT-B/16 (MIT), CPU, `.venvs/{croma,dofa}` |
| Probe | `sklearn` `StandardScaler` + `LogisticRegression(C=1, class_weight=balanced, max_iter=5000)` on frozen features |
| Arms | A = CROMA `optical_GAP` · **B = CROMA `joint_GAP`** · A′ = DOFA S2 feat · **C = DOFA S2⊕S1 concat** |
| Significance | 2000× bootstrap over the eval set for macro-F1 CIs + paired-delta CIs; exact McNemar on discordant predictions |
| Runtime | CROMA feature extraction 154 s / 400 patches (0.38 s/patch, 1.47 GB RSS); DOFA 106 s (0.26 s/patch, 1.20 GB RSS); probe 11 s. **CPU, no GPU.** |
| Harness | `evaluation/scripts/exp004_run2_{extract,features,probe}.py`; report `evaluation/reports/exp004_run2_20260902T111643.json` (+ `.md`) |

### Result (sanity-scale — 600 / 986 validation patches; a real integrated number, NOT a full DFC2020 benchmark)

| Arm | features | macro-F1 | accuracy |
|-----|----------|:--------:|:--------:|
| A · CROMA optical-only | S2 only, 768-d | 0.726 | 0.865 |
| **B · CROMA joint (SAR+opt)** | S1+S2, 768-d | **0.793** | 0.885 |
| A′ · DOFA optical-only | S2 only, 768-d | 0.725 | 0.890 |
| C · DOFA fused (SAR+opt) | S2⊕S1, 1536-d | 0.708 | 0.875 |

**Does adding SAR improve the task?**

| comparison | Δ macro-F1 | 95% CI (bootstrap) | CI excludes 0? | McNemar p | P(Δ>0) |
|------------|:----------:|:------------------:|:--------------:|:---------:|:------:|
| CROMA joint − CROMA optical | **+0.067** | [−0.024, +0.153] | **no** | 0.45 | 0.89 |
| DOFA fused − DOFA optical | −0.018 | [−0.065, +0.023] | no | 0.55 | 0.22 |

- **CROMA's native joint encoder: SAR gives a positive but *not statistically
  significant* gain** at n=200 eval (+0.067 macro-F1, CI includes 0, McNemar
  n.s.). The bootstrap puts P(SAR helps) ≈ 0.89 — a real signal, under-powered.
  Per-class: SAR lifts **Barren** F1 0.00 → 0.40 and **Forest** 0.83 → 0.87
  (classes where backscatter/structure carries information optical misses).
- **DOFA's S2⊕S1 concat fusion: no gain** (−0.018, n.s.). Late concatenation of
  two independently-encoded modalities does not recover the cross-modal signal
  CROMA's joint attention does.
- 0 non-finite features in any arm; 0 encoder failures.

### Decision — CROMA vs DOFA

Pre-declared rule: **1 downstream macro-F1 · 2 failure rate · 3 resource · 4
latency** (genuine tie → lighter deployment).

- **PRIMARY (macro-F1): CROMA joint 0.793 vs DOFA fused 0.708** — Δ 0.085,
  P(CROMA>DOFA) = 0.95. Not a practical tie (|Δ| ≫ 0.02). **CROMA wins the
  primary criterion**, and is the only arm where adding SAR helped at all.
- Secondary (failure rate): both 0 — no separation.
- Tertiary (resource) / quaternary (latency): DOFA is lighter (1.20 vs 1.47 GB
  RSS) and faster (0.26 vs 0.38 s/patch) — but only consulted on a tie, which
  this is not.

**KEEP = CROMA** for the optical–SAR path (capability D). DOFA is the
**challenger / fallback**. Feeds EXP-008 (adaptation runs on CROMA).

**H3 verdict:** *weakly supported* — optical+SAR improves the DFC2020 land-cover
probe via CROMA's joint encoder (+0.067 macro-F1), but the effect is **not
significant at this sample size**. A larger eval split (full 986, or the 5128-patch
DFC2020 test ROIs) is the honest next step before any strong "SAR improves
accuracy" claim. **INVESTIGATE → lean KEEP.**

### Smallest valid dataset (G6 Phase 5 decision — 2026-09-01)

The brief: *"Acquire the smallest valid real S1+S2 dataset... do not blindly
download large archives if an official smaller split exists."*

| Option | Real paired S1+S2? | Size | Verdict |
|--------|:-----------------:|------|---------|
| CROMA `DFC_preprocessed.pt` | yes | **11.2 GB** single pickle | ✘ too large, not subsettable |
| GFM-Bench `So2Sat.zip` | yes (LCZ) | 7.2 GB | ✘ |
| reBEN / BigEarthNet-v2 full | yes | multi-GB/shard | ✘ (subset possible but shards are big) |
| **IEEE GRSS DFC2020 — `ROIs0000_validation` (raw GeoTIFF)** | **yes** — `s1_*/`, `s2_*/`, `dfc_*/` (10-class label) | **≈ 1.5–2 GB** (986 patches, 256×256) | **✔ chosen** — official split, per-patch files (can stop at N=300–500), standard DFC2020 land-cover task |
| DFC2020 `ROIs0000_test` | yes | ≈ 6 GB (5 128 patches) | held out for the eval split |

**Chosen: DFC2020 validation ROIs (raw), subsample to a fixed 400 patches for
train + 200 for eval**, recorded by patch id. This is the *smallest* real paired
S1+S2 labelled set with an official split and a standard task, and it is
per-file so acquisition can be bounded. Source: IEEE GRSS DFC2020 (elib.dlr.de /
the competition mirror). Fallback if unreachable: SEN12MS 1 %-subsample by the
published tile list.

**Harness:** `evaluation/scripts/exp004_run2_probe.py` is written **on the remote
box** against the acquired file layout (a GeoTIFF DFC2020 loader is format-exact;
scaffolding it blind here would be guesswork). It reuses the Run-1 arm logic
(CROMA `optical_GAP` / `joint_GAP`; DOFA S2 / S2⊕S1) + `sklearn.LogisticRegression`
on frozen features. Referenced in `docs/deployment/REMOTE_GPU_SETUP.md`.

**Protocol (fixed now):** same 4 arms, same frozen-feature linear probe, same
split discipline (held-out, leakage-checked), seed recorded. Metrics: per-class F1
+ macro-F1 (+ mAP for multilabel), **abs and rel SAR delta**, explicit "where SAR
helped / hurt" examples, p50 feature-extraction latency. Then KEEP the better of
CROMA/DOFA for the SAR path (feeds EXP-008), or INVESTIGATE preprocessing if the
SAR delta ≈ 0 (`EXPERIMENT_DECISION_TREE.md`).

**This does not need a remote GPU** — both encoders run on the laptop CPU.
