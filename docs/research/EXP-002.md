## Question

Among released-weight single-image RS-VLMs that plausibly run on the dev host
(RTX 3050 Ti, 4 GB VRAM), which gives the best VQA + grounding quality per unit of
compute / integration cost — and does any clear the **minimum usability
threshold** below which a remote GPU (GeoChat) is justified?

## Minimum usability threshold (fixed before running)

A local candidate **passes** if, on the samples below:
- **VQA:** balanced accuracy ≥ **0.60** on RSVQA-LR yes/no + comparison questions
  (chance ≈ 0.5; the RSVQA-LR SOTA is ~0.90, GeoChat ~0.90 — 0.60 is a low bar for
  "usable in a demo with confidence-gating"), **and**
- **Grounding:** acc@IoU0.5 ≥ **0.30** on a DIOR-RSVG sample (chance ≈ 0), **and**
- **Latency:** ≤ **45 s / query** on CPU 4-bit (demo-tolerable with a spinner) or
  any latency on the 4 GB GPU.

If **neither** local candidate passes VQA **and** grounding → the remote-GPU gate
opens (`EXPERIMENT_DECISION_TREE.md`): rent one Linux GPU ≥ 16 GB, reproduce
GeoChat + GeoGround, re-run this experiment's remote arm.

4. `HF_HUB_ENABLE_HF_TRANSFER=1` + per-file resume, 8-min bound — reached only
   134 MB before the window closed; throughput < 1 MB/s with frequent drops.

**N = 0.** No VQA/grounding numbers. RSCoVLM-3B **not attempted** — it is a *larger*
(~6 GB) model from the same HF infrastructure; retrying it would repeat the failure.

### Why the remote-GPU gate opens now

The brief's literal gate is "both local candidates fail the predefined usability
threshold". That test **cannot be performed** — the artifacts are unfetchable from
this host, not measured-and-worse. The practical conclusion is identical: **there
is no viable path to evaluate a single-image VQA model on this machine.** A remote
Linux box provides (a) reliable bandwidth for the multi-GB weights and (b) the GPU
for GeoChat / GeoGround. **Recommendation: provision one remote Linux GPU ≥ 16 GB**
to run TinyRS + RSCoVLM-3B + GeoChat + GeoGround for capabilities A and B.

**Verdict: BLOCKED (artifact acquisition). Remote GPU justified — on
infrastructure grounds, not on a measured local failure.**
